# Screen program subset

`cnative lower <file>` lowers any screen class that stays in the subset below. It does not look at the file name. `Screen.cs`, `PackingScreen.cs`, and `SettingsScreen.cs` all lower through this subset. The running activity applies the record with `UseProgram`. The screen whose id is `counter` publishes `Count`, `Name`, `GreetingFirst`, and `PlainRoot` into `AppState`. The screen whose id is `packing` publishes `Items`, `Editing`, and the draft fields into `PackingState`. Any other screen keeps those values in its own bag. There is no activity per screen and no per-screen lowerer.

```sh
cnative lower samples/NativePoc.Settings/SettingsScreen.cs --json
cnative lower samples/NativePoc.Settings/SettingsScreen.cs --apply
```

`--json` prints one object. A program that lowers is `{"ok":true,"bytes":N,"hash":"..."}`. The hash is the first 16 bytes of SHA-256 of the source, hex. A refusal is `{"ok":false,"diagnostics":[...]}`. Each diagnostic has `id`, `message`, `start`, `end`, `line`, and `column`. `start` and `end` are UTF-16 offsets into the file. The process exits 1.

## What is accepted

A file is one namespace. It holds records or classes of state, and one static class with `public static Element Render(State state, IPlatform platform)`. The state type may live in the same file or be inferred from the `Render` parameter. `public const string` and `public static readonly string` on the screen class are values.

State properties are `string`, `bool`, `int`, or `List<T>` / `IReadOnlyList<T>` where `T` is a record whose fields are strings or bools. A get-only `int` is a flag count of the first bool field. A get-only `string` is the list text. Initializers are literals, a list of object initializers, or an empty `new List<T>()`. A reload keeps a value when the property name and type are still there. Methods on the state class are kept and are not seeded as properties.

The render body is one of:

- an expression, or a single `return`
- a chain of `if (condition) return element;` ending in `return element;`
- `var rows = new List<Element>();` with `Add` calls before and after one `foreach`, then `return` of a `ScrollView`, `ListView`, or column of that list

Elements are `Text`, `Button`, `TextField`, `TextInput`, `Switch`, `Column`, `ScrollView`, `ListView`, and `Image`. A column's children are arguments or a collection expression. `Key` is a string literal, or an item string field (`Key = item.Id`). A parent may mix keyed and unkeyed children. Keyed children match by key. Unkeyed children match by position among the unkeyed children. `new ListView(rows) { Key = "..." }` is the recycled list. `new Image("marker")` names a drawable resource. `Side` is the dp edge of that view. `0` keeps the 48dp touch floor. `new Image("https://...")` names a remote bitmap when the build sets `NativePocHttp`.

An element may set `Style = new Style { ... }`. The fields are `Padding`, `Margin`, `Gap`, `Grow`, `Align` (`Align.Start`, `Align.Center`, `Align.End`, `Align.Stretch`), `FontSize`, `Weight` (`FontWeight.Regular`, `FontWeight.Bold`), `Radius`, `Color`, `Background`, `Across`, `Wash`, and `Stroke`. Numbers are dp except `FontSize`, which is sp. `Color`, `Background`, `Wash`, and `Stroke` are `0xAARRGGBB`. Zero means unset, so a styled child does not clear the root padding. `Across` is 0 for a vertical column and 1 for a horizontal one. A horizontal column splits the width left after its padding and the gaps, so the two margins stay equal and each child stays inside the parent. `Grow` on a child of a horizontal column is a width weight, and `cnative inspect` does not call that a fixed height. `cnative inspect` adds `overflow` when a child extends outside its parent and is clipped, and `system-bar` when a child sits in the top 24 dp, which the host reserves for the status bar. `Wash` with `Background` paints a top-to-bottom gradient. `Stroke` paints a 2 dp outline. The first frame paints a rectangular fill of that gradient, with no corner clip, and the radius, gradient, elevation, and stroke follow on the chrome callback. `cnative inspect` code `contrast` fails when a text misses contrast against that first-frame color. A style-only edit is a `SetStyle` patch on the same view.

A `TextField` or `TextInput` may also set `Keyboard` (`Keyboard.Text`, `Keyboard.Email`, `Keyboard.Number`, `Keyboard.Phone`, `Keyboard.Password`), `Lines` (above 1 is a multiline field), `Submit` (`Submit.None`, `Submit.Next`, `Submit.Send`, `Submit.Go`, `Submit.Search`), and `OnSubmit`. `OnSubmit` is a lambda with the same actions as a button, plus `state.Name = state.Other.Length == 0 ? "missing" : ""`, `state.Flag = state.Other.Length != 0`, and the platform modules in [platform-modules.md](platform-modules.md). `TextInput` lowers to the same field opcodes as `TextField`. Autofill is off unless the field sets `Autofill = true`. Off leaves `ImportantForAutofill` off. The notes fields leave it unset, so they do not autofill. The host keeps the caret for a field whose key and text stay put across a reload. `cnative agent submit <id>` runs `OnSubmit`. The notes draft is a `TextInput` with `Keyboard.Text`, `Submit.Send`, and `OnSubmit`. The note title uses `Submit.Go`. The note body uses `Lines` 4.

The render body may start with `platform.Effect("Property", "resource")` and `platform.Every("Property")`. `Effect` names a string property and a local asset (`resource` + `.txt`). The host starts one task for that pair. A reload while the task is pending does not start a second task, and the task writes the property once. `Every` names an int property. It does not run a timer. `cnative agent clock` adds one to each armed property.

Expressions are string literals, `+`, `$"..."` with holes of the same expressions, `condition ? a : b` of texts or of elements, and parentheses. A condition is a bool property, `true` / `false`, `property.Length == 0`, string equality, or any bool expression the action VM can evaluate, including `state.Count > 0`. An `if` / `else` whose branches each return an element is the same jump. An `if` without an `else` may return early. An int property interpolates as a decimal. `foreach` reads item string fields and item bools. A method in the same file that returns an `Element` can be the element a row adds, as in `rows.Add(Row(item))`.

An action is a lambda. The running process interprets it with a switch in `RecordProgram.RunSteps`. That switch is compiled into the NativeAOT binary. An action does not call `Assembly.Load` and does not generate code. The forms opcodes 1–33 already name stay in that encoding. Anything else is one `ActVm` program, a stack machine in [architecture.md](architecture.md). One tap stops after 100000 steps. The log line is `action stopped after 100000 steps`. Where the same C# would throw, the action stops with that exception's message. The writes so far stay, and the host asks for a render. The process stays up.

An action may:

- assign a property from the lambda argument, a literal, a property of the same kind, or an item field
- use `+`, `-`, `*`, `/`, `%`, and unary minus on int and double. Integer `/` and `%` match C#, including the overflow of `int.MinValue / -1`. Integer divide by zero stops with `Attempted to divide by zero.` Double `/` and `%` do not stop: `1.0 / 0.0` is infinity
- use `<`, `>`, `<=`, `>=`, `==`, `!=`, `!`, `&&`, and `||`. `&&` and `||` skip the side that must not run
- use `property++`, `++property`, `property--`, and `--property` on an int, as a statement or as a value (`var n = ++state.Count`)
- use `+=`, `-=`, `*=`, `/=`, and `%=` on an int, and `+=` on a string
- use `flag = !flag`, `flag = !other`, and `flag = other` on bools
- concatenate strings with `+`, `+=`, and `$"..."`. A hole may be any expression the VM can evaluate, including arithmetic
- use `value = condition ? a : b`, and `if` / `else`. An `if` that the older condition opcodes can name stays those opcodes and nests at most eight deep. Any other condition is a jump in the VM. A bare `return;` stops the rest of that action. Statements after it do not run. A `return` with a value uses the helper return path
- use `try` / `catch` / `finally`. One `catch` and one `finally` are a region. Several `catch` clauses are nested regions, and the first matching type wins. `catch` with no type matches any user exception. `catch (FormatException)` does not swallow `DivideByZeroException`. `catch (Exception)` and `catch (ArithmeticException)` do, because the match walks the exception's base types. A `throw` inside `if` is still caught by the `try` that contains that `if`. `finally` runs on the way out, including after a caught exception, and an exception thrown in `finally` replaces the one that was pending. The catch variable is not bound: `catch (Exception ex)` is refused when the block reads `ex`. A `when` filter is refused. `return` inside `finally` is refused. An exception with no matching handler stops the action with that exception's message, the same words as compiled C#
- use `for`, `while`, and `foreach` over a state list. `foreach` walks a snapshot of the list taken at the start of the loop. The body may read `item.Field`. `list.Remove(item)` during that walk drops the row and the loop continues with the next snapshot row. `foreach (var item in state.Items.ToArray())` is the same walk. Compiled C# over `List<T>` still uses that list's enumerator, so the parity compile rewrites the loop to `ToArray()` and a screen in the APK does the same when the source writes `ToArray()`
- use `?.` and `??`. `?.` does not call when the receiver is null. `??` replaces that null
- declare one local at a time, `var` or a typed name, of int, double, string, or bool. An action has eight slots. A local stays visible for the rest of that action. A second `var` of the same name is refused. `string label = null` stores null
- call `list.Add(new T { Field = cell })`, `list.Clear()`, `list.RemoveAt(index)`, and, on the row a `foreach` is visiting, `list.Remove(item)`, `list.Contains(item)`, and `list.IndexOf(item)`. `list.Count` is the row count. A cell is a string literal, a string property, a string local, or a bool literal. A missing cell is `""` or `false`. `RemoveAt` past the end does nothing. On that same row, `item.Flag = !item.Flag` flips a bool field. The row's first string field is the id the flip addresses
- call `PersistRows.Encode(state.Tasks)` or `PersistRows.Encode(state.Tasks, item => new[] { item.Id, item.Title })` as the string argument of `Persist.Put`. The extra argument is a lambda. The reload VM reads that lambda and writes the wire cells in the lambda's order, not the property declaration order. `PersistRows.Fill` reads the third lambda the same way and puts each wire cell back into the named field. A length prefix lets a title contain a newline. `PersistRows.Fill(state.Tasks, state.Saved)` and the same call with a third lambda argument replace that list from the string `Persist.Get` stored. A string that is not the codec leaves the list as it was
- call `Trim`, `ToUpper`, `ToLower`, `Contains`, `StartsWith`, `Substring`, and `Length` on a string. `ToUpper` and `ToLower` use the invariant culture. `Substring` past the end stops with the `ArgumentOutOfRangeException` message. A null receiver stops with the `NullReferenceException` message
- call `Math.Min`, `Math.Max`, `Math.Abs`, and `Math.Round`. `Round` uses midpoint-to-even and returns a double. Storing a double in an int needs `(int)`
- call `int.Parse` and `int.TryParse(text, out var name)`. A bad or overflowing parse stops with the `FormatException` or `OverflowException` message. `TryParse` is the one `out` the VM accepts. `(int)` of a double matches the C# cast, including NaN and values past `int.MaxValue`
- call `platform.RequestRender()`, `platform.Pulse()`, `platform.CopyNonce` with a string literal, a string property, or `"poc-" + state.Count`, `platform.CopyText` with a literal label and the list text, `platform.Push("screen-id")`, `platform.Push("screen-id", item)` from the row a render `foreach` is visiting, `platform.Push("screen-id", state.List[0])` with an int literal index, `platform.WriteBack()`, `platform.Pop()`, `platform.OnOpen(ScreenId, Open)` where `Open` is a local function declared first in `Render` and `ScreenId` is that screen's const, and `platform.Effect`. `OnOpen` runs that function when the screen id differs from the last one this platform opened. A `RequestRender` and a hot reload of the same id do not run it. Coming back from another screen does. `samples/tasks` loads its saved rows there. `Push` of a row copies that row's fields onto the destination screen's properties of the same name and stores the route in the destination bag. The row id is the string property named `Id`, or the first string property when the record has no `Id`. A row with no string property is refused: `Push copies same-named fields onto the destination screen. The row needs a string property.` The index form copies the same fields from that list slot. `WriteBack` writes those properties back onto the source row. The route strings are part of the nav checkpoint, so a reload keeps them
- call `state.Commit()` and, inside a foreach, `state.Drop(item)`
- call a private static method or an instance method declared in the same file, with int, double, bool, or string parameters. The methods may call each other, and a method may call itself. Recursion stops after 64 calls with `action stopped after 64 calls`. A method that returns an `Element` is a render helper, not an action call
- call `Haptics.Confirm`, `Share.Text`, `Clipboard.Copy`, `Storage.Set`, `Storage.Get`, `Theme.Mode`, `Http.GetJson`, `Http.PostJson`, `Timer.After`, `Location.Read`, `Persist.Get`, `Persist.Put`, `Persist.GetRecord`, `Persist.PutRecord`, `Nav.Push`, `Nav.Pop`, and `FeedModule.Apply` as in [platform-modules.md](platform-modules.md)
- assign `state.Name = await Http.GetJson(platform, url)`, and the same shape for `Http.PostJson`, `Storage.Get`, `Timer.After`, `Location.Read`, `Persist.Get`, `Persist.Put`, `Persist.GetRecord`, and `Persist.PutRecord`. The URL or key is a string literal or a string property. `Timer.After` takes an int literal. `Location.Read` takes no extra argument. A finished task writes the string and continues. A task that is still running suspends the action and resumes on the UI thread. Each segment has its own 100000-step budget. `if (state.Json.StartsWith("http-error:"))` is a condition. A local function in `Render` with no parameters can hold that handler, and both a button and `OnRefresh` can call it. `samples/visit` is a form that validates a `TextInput`, pushes a row to `stop`, reads location, fetches JSON, and remembers a place. It compiles only when both `NativePocHttp` and `NativePocLocation` are set, so a counter Release does not contain it. Remember and Recall call `Persist`. The file store is compiled only when `NativePocPersist` is set. `samples/notes` is a list, a detail screen, and an edit screen on that same `Nav.Push` and `Persist.Put`. It compiles only when `NativePocPersist` and `NativePocNav` are both true. `Show` replaces a program and does not push, so a cold launch of `notes` is one screen. `Push` builds the stack, and a checkpoint restore puts that stack back.

These stay refused. The VM has no arm for them, and a reload cannot invent one:

- `await` of a call that is not `Http.GetJson`, `Http.PostJson`, `Storage.Get`, `Timer.After`, `Location.Read`, `Persist.Get`, `Persist.Put`, `Persist.GetRecord`, or `Persist.PutRecord`, and `await` that is not assigned to a string property
- a call that is not in the list above, including `state.Title.Normalize()`. The table is a switch, not a lookup
- a new type, or a generic that the edit instantiates for the first time. The binary was compiled without it
- `out` and `ref` other than `int.TryParse`, two names in one declaration, a list-typed local, a nested lambda, and assigning one list to another

`cnative run android --restart-on-rude` relaunches the installed process. The C# compiler then puts that method or type into the next binary. The relaunch keeps the checkpoint.

A `public const string ScreenId` names the screen on the stack. Each id keeps its own record across a reload. A `PackingTelemetry` increment inside an action is a no-op in the program. The C# method still increments.

`cnative agent tree` prints one `stack N id` line per frame, from the bottom of the stack. `Show` updates the program. A show of an id that is not on the stack appends it. A show of the current top leaves the stack where it is. A show of an id already further down moves that frame to the top and does not add a second copy. Frames that were above it stay on the stack, underneath it. That is the same stack effect as `Push` of an existing id. It is not React Navigation's `navigate`, which pops back to the existing screen and drops every screen that was above it. `Push` of an id that is not on the stack appends it. `Push` of an id already on the stack moves that frame to the top and leaves the other frames in order. It does not add a second copy. `Push` of the current top leaves the stack where it is. The stack is also the `NAV` trailer after the STC1 packing note. The version byte stays 1 or 2. A checkpoint without that trailer still loads. Bytes that are not the trailer are rejected.

`Theme.Mode` takes `dark`, `light`, or `system`. `system` follows the device night mode. Font scale is the system setting. Text uses `sp`. `cnative inspect` adds `fixed-height` when text sits in a `Grow` slot, or when the box does not get taller at font scale 2. It adds `overflow` when a child extends outside its parent, including at font scale 2. It adds `system-bar` when a child sits under the status bar. It adds `button-label` when a button is taller than 56 dp, which is the height where a top-aligned label leaves a gap. The host centres the label and clamps the control to 48–56 dp before the font scale. The Android host applies system-bar insets on the content root of every screen, and keeps the design padding inside that inset so a heading cannot scroll under the status bar. Notes and visit do not use `Grow`, so that lint is empty on both.

A running `cnative run android` prints `path:line:column: id: message` and `The edit was not applied. The last program stays until relaunch.` The device overlay shows `file:line` on the first line and the message under it. The log is `dev-overlay id=` with `file=` and `message=`. A runtime exception in a handler uses that same overlay and leaves the last tree up. A compiler error in `Screen.cs` puts `error CSxxxx` in the overlay. The next save that applies clears it. `--restart-on-rude` relaunches the installed process without publishing again, restores the checkpoint, and applies the last program that lowered. A Core or Android edit still rebuilds first. A parse error in a generated screen is `subset.not-a-screen` and uses that same relaunch. A parse error in `Screen.cs` is the compiler's `error CSxxxx` line, and that process stays up. Debug writes `files/nativepoc-state.bin` from `StateStore` on each render, including the nav bags, and the launch does not delete that file. A reload keeps a bag value when the property name and type are still there, because `Seed*` writes only when the key is missing. Changing `"Hello"` to `"Hello again"` leaves the heading on `Hello`. The apply reply then adds one line, `state kept Title="Hello" (initializer "Hello again"). cnative reset-state`. Several kept properties share that line, separated by commas. A first show has no keys, so it prints no line. A string literal in the render does change. `cnative reset-state` zeros the counter `AppState`, restores the packing sample list, deletes `files/nativepoc-state.bin`, replaces every nav bag, and applies the screen on top again so the initializers show. The next render writes a new state file from that reset. Only the `counter` screen reads and writes `AppState`. Only the `packing` screen reads and writes the packing list. A generated `notes` screen with its own `Count` does not inherit the counter.

## Scroll

`ScrollView` is one keyed child. The Android host maps it to `android.widget.ScrollView` (`FillViewport`) and reconciles that child by key, the same way a column reuses a row. The packing list is a `ScrollView` of key `scroll` around the `list` column, in `PackingScreen.cs` and in the lowered program.

`ListView` is a keyed list of rows. A build with `NativePocRecycler` (the listener, and a feed Release that passes `-p:NativePocRecycler=true`) maps it to `nativepoc.KeyedList`, a Java `RecyclerView` compiled into the APK. The managed `Xamarin.AndroidX.RecyclerView` assembly is not a compile reference. The Java class calls two JNI methods, `nativeSignal` and `nativeBind`. The adapter's stable id is a hash of the row key. `Style.Across` of 2 or more selects `GridLayoutManager` with `setHasFixedSize(true)`, an initial prefetch of 4, and a recycled-view cache of three times the column count. One column stays a `LinearLayoutManager`. The Northroom shelf is that grid, key `grid`, and the row keys are the piece ids. For a window that key is the first non-empty cell, read without building the row. A view holder is created once and rebound. `SetList` calls `notifyDataSetChanged` and does not scroll to row 0. If that notification leaves the first visible row at 0 after a list that was already scrolled, the host scrolls back to the saved index and logs `restored=1`. The log line is `list-first=`. The list's content description is `List`. `FeedRows.Window` is what `samples/feed/FeedScreen.cs` returns. A direct `Render` call puts the header in the column and the rows in a `ListView`. The lowerer treats that call as the same gathered column, so a list longer than 24 is still a window. A build without the flag, including the counter Release, still maps `ListView` to a `ScrollView` that keeps 20 slots. A window, a deferred list, or a list of more than 32 rows is one list node, and those rows are not id-tree children. A shorter list is walked, which is how the shelf tiles stay in the tree. A Release feed defines `NATIVEPOC_LAZY_FEED`, so `FeedScreen.Render` returns `FeedRows.Lazy` and builds each row element the first time it is indexed. The lowerer does not define that symbol, so it still sees the `foreach` and lowers a window. `built=` is that window's built count, or the deferred list's built count. The intent extra `nativepoc_bind_log=1` times JNI `onBind` and the C# parts (row index, face, text, image) and logs `bind-jni` and `bind-part` when the scroll goes idle. Release leaves the flag off.

A `foreach` of more than 24 rows does not build those rows during the first eval. It pushes one `ListView` whose rows are a window. Indexing a row runs that row's body, so a scroll that asks for the visible slots builds those slots and leaves the rest unbuilt. A list of 24 rows or fewer still expands, which is the packing screen's own four rows (the switch, the edit button, and the swipe stay on those rows). The 1000-row bench is the window. Headers and footers around the `foreach` stay in the column. A window slot shows the row's first text, a second text when that text is not empty, and an image when the source is not empty. Those three make different heights. The height of a row that has not been built yet is one text line, so the first frame does not evaluate every row. When the parent measures the window with an unbounded height, the window takes at most one screen and scrolls itself. The slot's key is the row key. Scrolling a slot onto a different row replaces that slot's title, subtitle, and image from the row it now shows. The switch and the button stay on the expanded list.

An `Image` with an empty source is hidden. A drawable whose file starts with `<`, which is how the vector markers are stored, uses `SetImageResource`. When `NativePocHttp` is set, a remote `http` or `https` URL and a bitmap resource such as a PNG are decoded on the thread pool. The view shows a gray placeholder, content description `Loading image`, until the bitmap is ready, or a red drawable, content description `Image failed`. An in-memory cache of 32 bitmaps applies a hit on the UI thread without that placeholder. A row rebound before the decode finishes drops the late bitmap and logs `image-drop`. The counter Release does not set `NativePocHttp`, so that path is not in the binary.

`HostView` is a platform view. `new HostView("webview", "url", state.Url)` names the kind, the prop, and the value. `Event` and `OnEvent` are the event name and the script. See [native-view.md](native-view.md). `L.Get`, `L.Format`, and `L.Plural` are the locale helpers in [localization.md](localization.md). `L.Plural` chooses the `one` string when the count is 1 and the `other` string otherwise.

## Accessibility

`ScreenSnapshot.Role` is the role. The host widget is the platform role, and the accessibility label is `contentDescription`.

| element | role | Android class | content description |
| --- | --- | --- | --- |
| Column | column | `android.widget.LinearLayout` | none |
| Text | text | `android.widget.TextView` | the text |
| Button | button | `android.widget.Button` | the label |
| TextField, TextInput | textfield | `android.widget.EditText` | the label |
| Switch | switch | `android.widget.Switch` | the label |
| ScrollView | scroll | `android.widget.ScrollView` | none |
| ListView | list | `nativepoc.KeyedList` when `NativePocRecycler` is set, otherwise `ScrollView` (20 slots) | `List` on the Java list |
| Image | image | `android.widget.ImageView` | the source, or `Loading image` / `Image failed` while a bitmap is in flight |
| HostView | host | the view named by `NativeViews` | the prop value |

`FontSize` is sp. The host calls `SetTextSize` with `ComplexUnitType.Sp`, so a system font scale of 1.3 or 2 grows that text. A `Text` whose `FontSize` is at least `ThemeTokens.HeadingSize` (22) sets the accessibility node heading flag on API 28 and later (`AccessibilityNodeInfo.setHeading` from a `View.AccessibilityDelegate`). Buttons, switches, text fields, and any view with a gesture are at least 48dp on each side. The counter, notes, and feed titles use `FontSize` 22 so they are headings. The API 34 emulator image's `uiautomator.jar` does not write a `heading` attribute, so `cnative agent a11y --check` reports `heading-attribute=absent` on that image. The host logs `a11y-heading` when the node is initialized.

`cnative agent a11y` prints `class`, `desc`, `text`, and `bounds` from `uiautomator dump`. `cnative agent a11y --check` reads that dump plus `wm density` and `settings get system font_scale`. It exits 1 when a clickable or long-clickable control is under 48dp, a button, switch, image, field, or text control has no text and no content description, a leaf sits above the previous leaf in the same column, or a text line is shorter than 16sp at the current font scale. A control whose bounds stop on the scroll view's bottom edge is partly off screen, and an empty `android.view.View` is the decor inset. Neither is a violation. The report includes `headings=N`. When the dump has no `heading` attribute it also says `heading-attribute=absent`. A `tests/device` step `a11y <text>` asserts that dump. The check itself does not need the hot-reload listener.

## Layout, logs, and the clock

`cnative agent layout` prints `id`, `left`, `top`, `width`, and `height` for each element, from the mounted view. `cnative agent logs` prints `logcat -d --pid=<app> -s NativePoc:I NativePoc:W NativePoc:E` for the running process.

An element may set `OnTap`, `OnLongPress`, `OnSwipe`, or `OnRefresh` to a lambda with the same actions as a button. `OnSwipe` is a horizontal swipe. On a packing row it removes that row. `OnRefresh` belongs on a `ScrollView` or `ListView` and can call `platform.Effect`. A reload that keeps the view keeps the gesture; a reload that removes the view does not dispose it until the gesture ends. `cnative agent swipe <id>` runs `OnSwipe`.

`Animated.Timing(platform, key, from, to, duration)` and `Animated.Spring(platform, key, from, to, duration)` scale the view with that key. `from` and `to` are percents. `duration` is the basis in milliseconds. The running duration follows `MotionScale`: either system scale at 0, or a basis of 0, snaps to `to`. A screen that never calls them does not post a frame callback.

A `Motion` initializer animates opacity, translation, and scale. `FromOpacity`, `FromX`, `FromY`, and `FromScale` are the start. `Opacity`, `X`, `Y`, and `Scale` are the end. `Duration` is milliseconds. `Easing` is 0 linear, 1 decelerate, 2 accelerate, or 3 accelerate-decelerate. A fresh view starts at the from values. A reload that keeps the view continues from the value it has reached. On Android the running animation is a `ViewPropertyAnimator`. `Animate.Play(platform, key)` replays the motion last mounted on the view with that key. The notes heading and each new note row declare a motion, and add and delete call `Animate.Play` for the heading. `cnative agent clock` steps those motions by 100 ms and answers `animations=N`. When no screen has called `Every`, it also answers `clock=0`. After a screen arms an int with `Every`, each call adds one to that property and answers `clock=N`, where `N` is how many times the verb has stepped. The clock does not move between calls. Outside that agent clock, the same motion runs on the display's clock.
