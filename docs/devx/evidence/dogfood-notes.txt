## The two fixes

Empty `new List<T>()` was `subset.unknown-expression` because a list creation with no initializer was not an element list. It now lowers as an empty list. Tested: `An_empty_list_initializer_lowers`.

A bare `return;` in an action was `subset.bad-lambda`. The action now lowers as one VM program, and that `return` jumps to the end, so the Add does not run. Tested: `A_button_can_return_early_when_a_field_is_empty` (the error is set and the list stays empty). The device check is the empty Add on pid 9237.

Two other forms were not sent to the device. `Storage.Set(platform, "notes-open", item.Id)` does not lower, because a module argument is not an item field. The screen assigns `state.OpenId = item.Id` and stores `state.OpenId`. `state.Notes.Remove(item)` from the row button does not see the row binding, because each action starts with that binding cleared. The screen calls `state.Drop(item)`, and that delete ran on pid 9237.
