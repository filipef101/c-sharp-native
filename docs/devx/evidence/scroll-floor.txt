## Java list floor

`tools/bench/list-floor` is a plain Java `RecyclerView`. No C#, no Kotlin. Package `com.scratch.listfloor`, activity `com.scratch.listfloor.ListFloorActivity`, log tag `Floor`. One thousand rows, the same row shape as the feed (title, hidden subtitle, image slot at `ceil(48 * density)`, gray placeholder, content description `Loading image`), list content description `List`. Stable ids are the row position. `tools/bench/build-list-floor.sh` compiles it the way `build-floor.sh` compiles the empty cold-start floor: aapt2, d8, zipalign, apksigner. `tools/bench/fetch-androidx.sh` downloads recyclerview 1.2.1, core 1.3.2, customview 1.0.0, collection 1.0.0, and annotation 1.1.0 from Google Maven into `tools/bench/list-floor/.cache`, which is gitignored, and refuses a file whose sha256 is not the pin in `deps.sha256`. `gen_library_r.py` writes `androidx.recyclerview.R` and `androidx.core.R` from the library `R.txt` index order. There is no native library. The same APK bytes are the x86_64 and the arm64 artifact.

Built from the fetched jars, signed APK 531,381 bytes, sha256 `d7ffd1727fe71891e53e1e4e5ef8f058bdc5de70f3047d45a8f7c742dbc97c88`. Every zip entry except `META-INF` matches the earlier signed file sha256 `213a23ec384a8a22be27f0613394bc9f9a5a06591d6e44485420a29c4b166ef6`. The signature differs because the script makes a new keystore. One dex, 1,135,024 bytes, sha256 `148bac8f9014a456bd66f753883ced2293d32d18139548cefa0ca3e8d70d75df`. The dex contains `kotlin` 0 times. A sha256 mismatch in the pin file fails the fetch with `sha256 mismatch for <name>` (checked by pointing the script at a zero pin).

`scroll-bench.sh --run label:apk:component[:extras]` runs several APKs the way `mac-bench.sh --run` does: each round launches every APK once before the next round. ## Bind time

The intent extra `nativepoc_bind_log=1` turns the histogram on. Release default is off, so a normal feed launch does not time binds. Java records nanoseconds around `nativeBind` only (cap 512) and logs `bind-jni` on scroll idle. C# times the row index, `RowFace.Read`, the text set, and `PictureBinder.Show`, and logs `bind-part` on the same idle. The histogram is every bind since the process started. The last line of each feed round:

```
n=77 jni p50=129 p90=190 max=45935  row 2/3/8    face 1/2/15 text 64/79/5735  image 27/43/45718
n=80 jni p50=120 p90=197 max=23395  row 2/3/7    face 1/2/6  text 62/83/10228 image 26/36/16039
n=79 jni p50=128 p90=286 max=28450  row 2/5/1337 face 1/2/40 text 61/93/2933  image 26/61/28355
```

Units are microseconds. A typical bind is about 125 µs inside JNI. Of the C# parts, text is the largest usual slice (about 60 µs), then the image call (about 26 µs), then the row index (about 2 µs) and the face read (about 1 µs). The max is one slow image or text bind. The four parts sum to about 90 µs; the rest of the JNI sample is the transition and the view wrapping.

## Animation

`Motion.Easing` is 0 linear, 1 decelerate, 2 accelerate, 3 accelerate-decelerate. The codec is 20 bytes. Android plays opacity, translation, and scale with `ViewPropertyAnimator`. `Animate.Play(platform, key)` is the module `animate` / `Play`. The notes heading and each note row declare a motion. Add and delete call `Animate.Play` for the heading. A reload of the duration is the same process.

Emulator-run, listener, `IsDynamicCodeSupported=False`, no `--restart-on-rude`. After `pm clear`, pid 30214 logged `motion play key=heading duration=180 easing=1 source=mount`. The watcher (`cnative run android --listener --device emulator-5554 --root notes`) started pid 30338 and logged the same line. Editing the heading duration from 180 to 420 reloaded in 25.3 ms (apply 23.3 ms), edit-to-reply 68 ms, same pid, and logcat printed `motion play key=heading duration=420 easing=1 source=mount`. Typing a note and tapping Add, still pid 30338, logged `motion play key=heading duration=420 easing=1 source=handler` and `motion play key=Hello duration=180 easing=1 source=mount`. The source was put back to 180. That reload was 22.8 ms (apply 19.3 ms), edit-to-reply 64 ms, same pid, `motion play key=heading duration=180 easing=1 source=mount`.
