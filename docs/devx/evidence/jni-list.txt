# JNI list, images, scroll bench, accessibility

Emulator-run on `emulator-5554`, API 34, `x86_64`, boot `56815464-4bc4-4f4c-a503-944cb91ab31f`, `-gpu swiftshader_indirect`. Not a phone. Not iOS. arm64 was built and not run.

The list is `nativepoc.KeyedList`, a Java `RecyclerView` compiled into the APK dex. C# registers two JNI methods, `nativeSignal` and `nativeBind`. The managed `Xamarin.AndroidX.RecyclerView` and `Xamarin.AndroidX.Core` assemblies are not referenced. The RecyclerView AAR stays in the dex because the Java class extends it. Kotlin stdlib and coroutines AARs are packed as dex only (`kotlin.jvm.internal.Intrinsics` is what `androidx.tracing` calls). The profileinstaller AAR is removed because its initializer needs `androidx.concurrent.futures` and crashed the process. The dex still contains the string `profileinstaller` once and `AbstractResolvableFuture` 14 times. The initializer is not in the APK.

## List behaviour, emulator-run

Listener pid 24848, `IsDynamicCodeSupported=False`, swiftshader. Command: `tools/devx/cnative run android --listener --device emulator-5554 --root feed`. No `--restart-on-rude`.

First bind: `list-first=0 saved=0 restored=0 rows=1000 built=9 views=9`. `image-apply source=feed_mark`. Eight swipes: `list-first=60 saved=60 restored=0 rows=1000 built=71 views=10`. Scroll logged `image-drop` for URLs whose row had been rebound. Changing the row bullet and saving reloaded in 43.6 ms (apply 33.4 ms), edit-to-reply 84 ms, same pid, `list-first=60 saved=60 restored=0 rows=1000 built=10 views=10`. The bullet was restored to `• ` on that pid. The row-width fix in `KeyedList.java` came after this pid. It does not change the bind or scroll path.

Release feed, pid 25124, same emulator: `list-first=0 saved=0 restored=0 rows=1000 built=1000 views=7` and `image-apply source=feed_mark`. `built=1000` is the C# `Render` prebuilding the row elements. The recycler view count stays at the visible rows. A later Release launch logged the same `list-first` shape.

## Scroll bench

`tools/bench/scroll-bench.sh` takes `--serial`, `--apk`, `--activity`, `--swipes`, `--rounds`, `--extra`, `--out`, `--wait`. It installs, launches, waits for logcat `list-first=`, then `dumpsys gfxinfo <package> reset`, swipes, and prints frames, janky percent, and p50/p90/p99 from framestats. Percentiles are Hyndman-Fan type 7. Host load is `uptime`. `--self-test` passed (`scroll-bench self-test ok`). The script is bash and does not use `declare -A` or `mapfile`.

Emulator-run, swiftshader, font scale 1.0, the final x64 feed APK, 8 swipes, 1 round. Host load 0.22.

```
summary_frames=116
summary_janky=66 (56.90%)
framestats_rows=115 framestats_janky=68 framestats_janky_pct=59.13
framestats_p50_ms=63.3 framestats_p90_ms=103.8 framestats_p99_ms=206.3
```

An earlier round on the same APK while a Release publish was running (load 1.51) was 103 frames, 72.82% janky, p50 77.6 ms, p90 110.6 ms, p99 145.5 ms. The jank is the software GPU. This was not a phone GPU.

## Images

`Image` takes a drawable name or an `http` URL. URL and bitmap resources decode on the thread pool. XML drawables stay on `SetImageResource`. The cache holds 32 bitmaps and does not call `Bitmap.recycle`. Placeholder and error are a new `ColorDrawable` per bind (`Loading image`, `Image failed`). A bind whose token is no longer current logs `image-drop` and does not set the bitmap.

Feed row 0000 uses `feed_mark` (16x16 PNG in `Resources/drawable`). Other rows use `http://10.0.2.2:8094/img/` plus the id. The server is `/tmp/feed-server.py` on `0.0.0.0:8094`. It is not in the repo. GET `/feed` waits 2 seconds and returns two items. GET `/img/<id>` waits 0.3 seconds and returns those PNG bytes.

The counter `.so` has no `BitmapFactory`, `HttpURLConnection`, or `RemoteImages`. The image path is behind `NativePocHttp`, the same flag as HTTP.

## Accessibility

Font scale 2.0 (`settings put system font_scale 2.0`), density 420. `cnative agent a11y --check` reported `violations=0` on the counter, notes, and feed. Dumps and screenshots: `a11y-counter-font2.xml`, `a11y-counter-font2.png`, `a11y-notes-font2.xml`, `a11y-notes-font2.png`, `a11y-feed-font2.xml`, `a11y-feed-font2.png`, and the matching `.txt` check reports.

Measured bounds. Headings are 123px (`Counter 0`, `Notes`, `Feed`). Body lines are 91px (`Enter a name`, `Day`). Buttons are 141px. The notes switch is 126px, which is 48dp at 420 dpi. The name field is 161px and the note field is 161px. Row text is 98px and full width. Nothing in those dumps is under 48dp when it is clickable. Text is not clipped at the bottom of its line.

Roles in the dump. Buttons are `android.widget.Button` with a content description. The name and note fields are `android.widget.EditText`. The dark control is `android.widget.Switch` with content description `Dark`. The feed list is `androidx.recyclerview.widget.RecyclerView`, content description `List`, focusable, scrollable. Images have the source as the content description, or the placeholder text while a bitmap is in flight.

Focus order in the dump, top to bottom. Counter: name field, Save, Packing. Notes: the scroll view, the switch, the field, Add. Feed: Refresh, Post, Back, then the list.

`headings=0` and `heading-attribute=absent` on this image. Measured: `/system/framework/uiautomator.jar` contains no `heading` string, so the dump cannot show the flag. The host sets it from an accessibility delegate when `FontSize` is 20 or more, and logcat printed `a11y-heading` during each of the three dumps. Font scale was put back to 1.0 after the screenshots. TalkBack was not run.

The counter title is a heading only after the catalog program was lowered again. The previous catalog bytes drew `Counter 0` at body size. `Screen.Render` already had `FontSize` 22. The Release counter shows the catalog program, not that method.
