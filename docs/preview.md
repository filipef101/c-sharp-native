## What hot reload refuses

`IsDynamicCodeSupported` is false, so the process does not compile new IL. The call table is a switch that was compiled into the binary. A lowerable body is stored as ActVm bytes and the next call in that process runs those bytes. A body the lowerer cannot name is refused in one sentence, and `cnative run android --restart-on-rude` relaunches. A method the table does not list, a new top-level type, a generic the edit constructs for the first time, and `await` of a call other than `Http.GetJson`, `Http.PostJson`, `Storage.Get`, and `Timer.After` are refused for the same reason: the binary has no arm, and a reload cannot invent one. The list is in [screen-program-subset.md](screen-program-subset.md). An edit under `src/NativePoc.Core` or `src/NativePoc.Android` is rude because the loader only swaps the screen assembly. That is written in [devx/comparison.md](devx/comparison.md).

The other toolkits, from their own pages and not timed on this boot, are in [comparison.md](comparison.md). .NET MAUI's .NET 10 page reloads XAML in a debug session with the debugger attached and states that it does not reload C#. Uno's page says it modifies XAML and C#. Avalonia's page plugs into .NET Hot Reload through `dotnet watch`, and C# follows those rules. This tree reloads a screen record, and it swaps a lowerable `[ReloadCallable]` body through the action VM.

## `cnative doctor`
