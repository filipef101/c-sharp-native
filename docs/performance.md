# Performance

Cold-start numbers for the default counter (`com.scratch.nativepoc`) and the showcase (`com.scratch.nativepoc.showcase`). Every row names the method. Percentiles are Hyndman-Fan type 7. A bootstrap interval is B=1000, Python `random.Random` seed 8946, and is the 2.5 and 97.5 percentiles of the resampled p50. `am start -W -S` TotalTime, LaunchState COLD, one discarded warmup. A sample is flagged when the post-sample guest load is above 2.0. A load of exactly 2.0 stays. The device is emulator-5554, API 34, x86_64, SwiftShader, unless a row says otherwise. `simpleperf` is on the image and was not recorded.

TotalTime is the first drawn window. Visually complete is the first frame that already has the chrome the user keeps. On this tree, fully drawn is that frame: the counter's flat button and field rule, and the showcase's styled chrome. A MacBook AVD named `pixel_fold_mc` is described in [../tools/bench/mac-pixel-fold.md](../tools/bench/mac-pixel-fold.md). That bench was not run.

## First frame

One `atrace` pair, before the placeholder, marks off, both packages `verify`. Counter TotalTime 891. Showcase TotalTime 547.

Counter, milliseconds from the process: PostFork 33.1, ActivityThreadMain 18.2, OpenDex 6.4, bindApplication 84.3, performCreate 24.6, activityStart 60.0, activityResume 5.3, view measure 1.9. The first `Choreographer#doFrame` is 571.1. Inside it, setSurface is 281.0 and the shader compiles are NonAALatticeOp 49.3, FillRectOp 54.1, ShadowCircularRRectOp 33.4, CircularRRectOp 47.7, and AtlasTextOp 7.8. `startup phase=nav` was 23 µs, `decode-ms=0`. Release does not open `nativepoc-state.bin` on that launch.

Showcase, same trace session: ZygoteInit 11.9, ActivityThreadMain 16.2, OpenDex 1.2, bindApplication 38.5, performCreate 23.2, activityStart 81.6, activityResume 3.7, view measure 3.8. The first frame is 248.7. Its shaders are AtlasTextOp and FillRectOp. setSurface is 91.6. `startup phase=state-load`, `nav-restore`, and `persist-read` were 0 ms. Both packages use `NativePocTheme`.

Holding the Material drawables off that frame and putting them back from `StartupMarks.AfterPresent` made TotalTime a frame with transparent buttons. `screenrecord` on that counter, 20 Mbps, 1080x2400, 31 frames in 6 seconds (about 5.7 fps; the tool has no frame-rate flag), caught one frame of ghost Save and Packing buttons, then the white Material buttons. That run's default button was the flat theme fill, and the field was the accent rule. The first captured frame of a later recording already has that gray fill, and the still after it matches. This tree's default button is the card fill, a 1dp hairline, and a ripple, with no elevation. One night cold start of that counter on emulator-5554, SwiftShader, TotalTime 899, was not a gated n=20. `dumpsys gfxinfo framestats` recorded 9 frames. The first is flags 1, 427.2 ms from its intended vsync, 138.2 ms from issue to swap. The next frame completes 38.5 ms later and spends 1.7 ms from issue to swap. The heavy draw is the first frame.

## setSurface

On this boot, one `am start -W -S` each, text `atrace`, RenderThread `setSurface` for the app process: empty Java floor (`com.scratch.floor`, one `TextView`, default theme) 153.3 ms, then the placeholder counter 223.5 ms, the showcase 308.7 ms, and the floor again 391.0 ms. TotalTime on those four starts was 803, 809, 772, and 820. The floor has no `NativePocTheme`, no hardware layer, and no splash color of ours. Its `setSurface` sits in the same range as the 281.0 ms slice, and the second floor start is the longest of the four. That cost moves with the emulator's GL setup. It is not a fixed slice of our window format.

## Baseline profile

`classes.dex` in the counter apk is 55,872 bytes. Install-time dex2oat at `compiler-filter=verify` took 67.601 ms inside a 113 ms ArtService wall time and wrote a 74,768-byte odex. OpenDex on the counter trace above is 6.4 ms.

A warm launch wrote `primary.prof`, 293 bytes, ART profile version 015. `profman --dump-only` matches the installed dex. The methods in it are the Java interop stubs (`MainActivity`, `StartupButton`, `AndroidField`, `NativeAotRuntimeProvider`, the mono listeners). Copying that file to `assets/dexopt/baseline.prof` and to `assets/art-profile/baseline.prof`, then re-signing, left the streamed install at `verify`. artd logged `Merge skipped because there are no existing profiles`.

`adb install-multiple` of the original apk and a `base.dm` (a stored zip of that `primary.prof`) did apply. dexopt became `speed-profile` / `install-dm`. dex2oat wall time was 118 ms and the odex was 129,544 bytes. The solo rows in the table are that install and a fresh streamed install of the same apk with no dm. The p50 moved from 591.5 to 580.0, and the intervals overlap. The template does not ship a `baseline.prof`. `NativePocAotProfile` is the NativeAOT profile, which is a different file.

## Fully drawn

`tools/bench/interleave-cold.sh` clears logcat after the guest gate, writes `nativepoc-sample <name> <index>`, and reads the first Fully drawn line for that package after the mark. The mark match stops before another digit, so sample 1 is not sample 10. `+1s40ms` is 1040 ms. `cold-start.sh --self-test` runs that parser check. Fully drawn is the visually complete frame: the counter reports it on the flat chrome, and the showcase reports it after the styled chrome has been drawn.
